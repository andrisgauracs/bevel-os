# Port to the Guition JC1060P470-V2 (ESP32-P4): status and how to continue

Work in progress, nothing committed. Board notes: `esp32_usb_cd_player/docs/JC1060P470-V2.md`.
Pins used by the OS: [main/board.h](../main/board.h).

## Build, flash, drive

- ESP-IDF **v6.1**: in PowerShell run `. C:\Espressif\tools\Microsoft.v6.1.PowerShell_profile.ps1` first.
- `tools\flash.ps1` builds, stops the serial daemon, flashes over COM13, restarts the daemon, prints the log.
- `python tools\bv.py daemon` holds COM13 (USB-Serial-JTAG). Then `bv.py cmd "<line>"`, `bv.py dump out.png`
  (RGB565 screenshot of what the panel shows), `bv.py reset` (sends `reboot`), `bv.py log`, `bv.py quit`.
  New serial commands: `usbdev` (list USB devices), `net`, `stat`.
- Apps: from a shell with ESP-IDF active, `bash tools/build_apps.sh` and `bash tools/build_doom.sh`
  (RISC-V, `-march=rv32imafc_zicsr_zifencei -mabi=ilp32f`). The ELFs in `disk/Apps` are now RISC-V builds.
- The old S3 `sdkconfig` and `dependencies.lock` were removed from the index (`git rm --cached`); new ones are
  generated and untracked. Scripts used for the edits are in the session scratchpad only.

## Open problem at the moment of stopping

The last two `idf.py -p COM13 flash` attempts failed with **"Failed to connect to ESP32-P4: No serial data
received"** (earlier flashes worked the same way). The board therefore still runs the previous firmware, which
lacks the libgcc exports Doom needs. Not investigated. Try: check that no `bv.py daemon` holds the port, press
RST, or BOOT+RST, then flash again.

| Ethernet | Link, DHCP address, SNTP time seen in the log. Browser over Ethernet **not tested**. |
| SD card | Mounted (32 GB card) as `/disk/SD`. Files-app changes (SD folder, free space, move between volumes) **not tested**. |
| Clock | RX8025T found at 0x32; it kept the time across a reboot. Taskbar shows the time once known. Time-zone list in Settings **not tested**. |
| Touch | GT911 detected. Nobody touched the screen: **not tested**. |
| Audio | I2S to the PCM5102 starts, mixer runs. **Nobody listened**: startup chime, message-box sounds, Sound Player (WAV) untested. |

## Not done

  modified copies in `p4_edge_enhancer/components`, built there on IDF 5.5.6, so they may need changes for 6.1),
  RGB565 frames into an overlay, snapshot to BMP. The app partition was enlarged to 4 MB for this.
- **Apps on the board**: Snake/Hello/CrashTest/Doom rebuilt for RISC-V but never run. The fault catcher
  (`__wrap_xt_unhandled_exception` in `app_loader.c`) is untested. Doom now uses the true-colour layer and has
  sound effects (no music); it needs `doom1.wad` in `/disk/Apps` or on the SD card (`tools/fetch_doom.sh`).
- Picture Viewer still dithers to 64 colours (could use an overlay).
- No on-screen keyboard and no right-click for touch.
- On-board ES8311 codec/speaker and microphone unused (amplifier kept off).
- README, `docs/OS-REPORT.md`, `docs/PERF.md`, `tools/kbtest.py`, `tools/powercut.py`, `tools/flash.sh` still
  describe the S3/VGA build. `enclosure/` is for the old hardware.
- Remove `disk/Music/Chime.wav` size if space matters (705 KB, embedded in the firmware).

## Things found on the way

- **Crash 1 (fixed):** the USB port watchdog power-cycled the root port with a hub attached:
  `assert failed: device_release ext_hub.c:512`. It now only cycles an empty port.
- **Crash 2 (worked around, cause not proven):** once, the saved context of the sleeping `sdcard` task was
  overwritten with network data (a Syncthing LAN broadcast) and the board reset. Ethernet was not started yet,
  so the data came through the C6. It happened in the one boot where the SD card was mounted while ESP-Hosted
  was still initialising its slot on the shared SDMMC controller. The SD task now waits for
  `ESP_HOSTED_EVENT_TRANSPORT_UP` (`os_c6_link_up`). Four boots since without a crash; that is not proof.
  It also means the C6 joins the Wi-Fi network saved by the CD-player firmware on its own.
- First boot after each flash takes about 9 s (bundled files are rewritten to the drive); the first boot on
  a blank flash took 25 s (format).
- ESP-Hosted logs `major version mismatch` (host 3.0.10, C6 firmware 2.12.13), as in the CD player.
- Firmware uses newlib (`CONFIG_LIBC_NEWLIB`), because apps import `FILE`/`errno`/`_ctype_` by name.
- The toolchain's libgcc is not position-independent: Doom is linked without it and imports those routines
  from the OS (`LIBGCC_LIST` in `app_loader.c`).
